## 2026-08-25 — Замер 0 AI Visibility: базовая линия, методика, контент-план

**Сделано:**
- Проведён замер 0 видимости в ИИ: 29 промптов (EN/RU/ID/TH/VI, слои
  problem/category/brand) × 2 прогона × 4 движка (Perplexity, Gemini, OpenAI
  web_search, Google AI Overview) = 223 ответа; разбор судьёй gpt-4.1-mini по
  строгой JSON-схеме. Промпты — из живых постов владельцев в FB-группах.
- Итог замера: brand-узнаваемость 83%, но в category-запросах («кто будет вести
  мой GrabFood») DB назван 0/76; шкала зрелости категории 97% → 16% → 2% —
  ИИ знает механику, но не знает о делегировании; consideration set занят
  POS-агрегаторами (Klikit 21 упоминание); Perplexity даёт предупреждение
  «treat Delivery Booster Bali as unverified»; коллизии имени (booster = реклама
  Grab; чужой софт «Delivery Booster»); thegrabmethod.com (одиночка с платным
  PDF) цитируется в 8% ответов.
- Новые документы: `AUDIT_METHOD.md` (методика, почему интервалы Уилсона и
  замороженный промпт-сет), `VISIBILITY_TRACKING.md` (таблица замеров, база
  2026-08-25), `CONTENT_PLAN_GEO.md` (4 направления + 5 черновиков FAQ RU/EN +
  дисамбигуация имени для llms.txt), `audit/` (prompts_v1.json — заморожен,
  audit.py — самодостаточный скрипт run/judge/report со сравнением с базой,
  baseline-2026-08-25/judged.json.gz — сырые данные).

**Решения:**
- Главная метрика роста — доля category-ответов с Delivery Booster (сейчас 0%,
  порог значимости ~7/76). Рост фиксировать только при непересекающихся
  интервалах Уилсона — audit.py считает это сам.
- Приоритет сдвинут: сначала «Доверие» (Clutch/About/LinkedIn/дисамбигуация —
  чинит «unverified»), затем контент про ДЕЛЕГИРОВАНИЕ (ниша пуста), и только
  потом остальной контент. Рынок не надо учить механике Grab — 97% ответов ИИ
  её уже объясняют.
- Вьетнам/Сингапур: категории делегирования в ответах ИИ не существует (0%) —
  контент туда образовательный, лидов из ИИ не ждать. Таиланд — самый зрелый
  (25%).
- FAQ-черновики НЕ вносились в faqs.ts — публичные тексты утверждает Алекс
  (CONTENT_PLAN_GEO.md §3).

**Следующие шаги:** P0 «Доверие» из BACKLOG; после утверждения — FAQ в faqs.ts
+ llms.txt + build + деплой; повторный замер через месяц по AUDIT_METHOD.md.
