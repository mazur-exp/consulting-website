## Правила работы

- **Пререндер обязателен.** Сайт — React SPA; ИИ-краулеры не исполняют JS. `npm run build`
  автоматически делает статические снапшоты всех роутов (`scripts/prerender.mjs`).
  Любая контентная правка требует полного `npm run build`, а не только vite build.
- **Новый рынок / кейс / FAQ = обновить три места:** конфиг в `client/src/config/`,
  `client/public/sitemap.xml`, `client/public/llms.txt`.
- **llms.txt** (https://booster.delivery/llms.txt) — витрина для ИИ: рынки, кейсы с
  цифрами, вопросы, формулировки услуг EN/RU. Обновлять при каждом значимом изменении.
- **Цифры в контенте — только реальные**, из презентаций кейсов или GrabMerchant/GoBiz.
  Ничего не выдумывать: этот контент цитируют ИИ. **Канонические цифры компании:
  «110+ ресторанов под управлением сегодня, 200+ обслужено с 2023 года».** Старые
  формулировки (90+, 85+ клиентов, «100+ клиентов», «12 клиентов») не использовать;
  если цифра меняется — обновить её ВЕЗДЕ разом (сайт, llms.txt, GBP, YouTube).
- **Внешние профили → `sameAs`.** Любой новый публичный профиль компании (GBP,
  YouTube, Instagram, LinkedIn, Clutch/Sortlist и т.п.) добавлять в Organization-схему
  (`client/src/components/SEOSchema.tsx`, `client/src/pages/about.tsx`) в массив
  `sameAs` И в `client/public/llms.txt`, затем `npm run build` + деплой. Это строит
  граф сущности (ИИ считает все профили одной компанией) и лечит «unverified» в
  Perplexity.
- **Один актив → пакет каналов.** Любая новая страница (данные, метод, ответ, кейс) сразу
  после деплоя разворачивается в пакет из пяти текстов: Telegram (RU), LinkedIn (EN),
  Instagram-карусель (EN, 6 слайдов + промпты картинок), короткий вариант для чатов (RU),
  ответ для Reddit-треда (EN). Порядок строгий: страница → деплой → проверка → GSC → посты.
  Правила языков, эмодзи, картинок и Reddit — в `CONTENT_PLAYBOOK.md`.
- **Имя основателя латиницей — строго `Aleksei Mazur`.** Везде: сайт, схемы, llms.txt,
  соцсети, каталоги, письма. Не Alexey, не Alexei, не Aleksey. По-русски — Алексей Мазур.
  Разнобой ломает граф сущности: для Google и ИИ это разные люди, и упоминания перестают
  складываться в одну репутацию.
- **Три языка: RU, EN, Bahasa Indonesia.** Функция перевода — `t(ru, en, id?)`, третий
  аргумент необязательный (непереведённое падает на английский). Контент в конфигах — поля
  с суффиксами `Ru`/`En`/`Id`. Индонезийская версия существует для ботов только как
  отдельные снапшоты в `lang-id/`, которые сервер отдаёт на `?lang=id`.
- **Новая страница = шесть мест, иначе её не будет ни у бота, ни у человека:** роут в
  `App.tsx`, запись в `scripts/prerender.mjs`, `sitemap.xml`, `llms.txt`, реестр
  `client/src/components/AnswersIndex.tsx` (если это ответ или актив) и живая `<a href>`
  с гейта или из FAQ-секции. Потом полный `npm run build`, деплой, проверка ботом,
  запрос индексации в GSC.
- **YouTube — по `YOUTUBE_PLAYBOOK.md`.** Правила ведения канала и чеклист на каждое
  видео (язык, теги, ссылки, EN+ID переводы) — там.
- Деплой идёт через Mac Алекса (git push + SSH на сервер) — из облачной песочницы
  прямого доступа нет. Детали в DEPLOYMENT.md.

## Архитектура сайта (состояние на 2026-09-08)

- `/` — гейт: гео-IP (api.country.is) → редирект на страну; неизвестно → окно выбора из 8.
  Выбор запоминается в localStorage (`preferredCountry`).
- `/id /th /sg /my /vn /ph /kh /mm` — 8 страновых страниц из одного шаблона + конфига.
- `/cases/*` — 6 полных кейсов с Article-схемой.
- `/answers` — хаб кластера (CollectionPage + ItemList) и 5 страниц-ответов под
  категорийные запросы; `/method` — метод целиком; `/benchmark` — оригинальные данные
  (Dataset + Article + FAQPage).
- Языки RU / EN / ID (`preferredLanguage`, `?lang=`), переключатель в шапке.
  Английский — снапшоты в корне, индонезийский — в `lang-id/`, сервер выбирает по `?lang=id`.
- Прод: 48 HTML-снапшотов для ботов, llms.txt, sitemap 24 URL + sitemap-index.

## Грабли, на которые уже наступали

Все три — один класс: в SPA мета-теги и маршруты принадлежат странице, а не шаблону,
и ошибка не видна ни в логах, ни глазом. Проверять при добавлении любой новой страницы.

| Симптом | Причина | Как чинится |
|---|---|---|
| Одинаковый `<title>` на всех роутах | `LanguageProvider` ставил свой title, а эффект родителя выполняется ПОСЛЕ эффектов детей и перетирал их | Title принадлежит странице. В провайдере — только `<html lang>`, canonical и hreflang (там этот же порядок используется намеренно) |
| `og:url` на каждой странице ведёт на главную; LinkedIn не строит превью | Все роуты наследовали og-теги из `index.html` | `syncOpenGraph()` в конце `useEffect` каждой страницы — зеркалит title/description/canonical в og: и twitter: |
| Страница молча отдаёт главную под своим адресом | `express.static` подставляет `.html` только когда пути нет вовсе; если есть папка с тем же именем (`/answers` и `answers/`) — проваливается в SPA-шелл | Снапшоты отдаются явным middleware до `express.static`, с проверкой `<path>.html` |
| Роут добавлен, но бот его не видит | Забыт `scripts/prerender.mjs` | Число снапшотов в конце сборки = роуты × языки. Сверять глазами |

**Проверка после каждого деплоя** (иначе баги этого класса проходят незамеченными):

```
curl -sA "GPTBot" https://booster.delivery/<route> | grep -o '<title>.*</title>'
curl -sA "GPTBot" "https://booster.delivery/<route>?lang=id" | grep -o '<html lang="[a-z]*"'
```

Заголовок должен быть свой у каждой страницы, `lang` — совпадать с запрошенным языком.
